# Toptal & Arc.dev — application prep

These platforms vet before you get clients. Prepare before applying.

## When to apply

Apply after:
- LinkedIn is complete
- GitHub has 1–2 public demos
- You can speak to 3 architecture stories with metrics

## Toptal — positioning statement

```
I'm a Technical Lead with 9+ years in Java, Spring Boot, microservices, and AWS, 
targeting Solution Architect engagements. I've delivered enterprise systems in banking, 
logistics, and transportation — including event-driven platforms with Kafka, cloud 
migrations, and CI/CD at scale. I combine architecture design with hands-on delivery 
and technical leadership (reviews, mentoring, stakeholder communication).
```

## Toptal — technical depth areas to emphasize

1. **Microservices:** boundaries, DDD, API design, resilience
2. **Kafka:** topics, partitions, consumer groups, exactly-once vs at-least-once
3. **AWS:** ECS/EKS, Lambda, networking, security basics
4. **Java/Spring:** Spring Boot internals, performance, concurrency
5. **System design:** trade-offs, scalability, CAP, caching

## Interview stories (prepare 3 STAR stories)

### Story 1 — Architecture decision
- **Situation:** Legacy monolith blocking releases
- **Action:** Defined microservices target state, phased migration
- **Result:** [Metrics from placeholders]

### Story 2 — Kafka / event-driven
- **Situation:** Need real-time [payments/tracking/events]
- **Action:** Designed Kafka topology, schemas, consumer patterns
- **Result:** Latency/throughput improvement

### Story 3 — Cloud migration
- **Situation:** On-prem cost/scale limits
- **Action:** AWS migration roadmap, K8s, CI/CD
- **Result:** Cost/uptime/release frequency
