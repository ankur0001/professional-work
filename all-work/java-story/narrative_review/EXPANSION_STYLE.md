# Narration technique (quality benchmark)

Use **EP01, EP04, and EP07** as the **narrative quality benchmark**, but do not mechanically copy their sentence patterns, paragraph structures, analogies, or transition phrases.

Extract the underlying teaching technique.

**Approved direction:** make every episode as narratively coherent and example-driven as EP01/04/07, while preserving each episode's own natural flow.

Do **not** ask for "more descriptive" content. Descriptive expansion is already solved.

---

## Final Narrative Quality Gate

Do **not** use word count as the primary measure of episode quality.

The ~10–12 minute / soft length band is only a guideline for episodes that genuinely require that much explanation. **Never** add filler, repetition, artificial examples, or unnecessary detail merely to reach a word count.

An episode is complete only when it passes **all** of the following tests:

### 1. Continuity Test

The episode must naturally continue from the previous episode.

The opening should assume the learner remembers the relevant idea from the previous episode instead of restarting the subject from zero.

### 2. Necessity Test

Every major concept introduced must feel necessary.

Ask:

> "What problem, limitation, observation, or question made the learner need this concept?"

If the only answer is "because this is the next topic in the syllabus," rewrite the transition.

### 3. Explanation Test

For every important concept, the learner should understand:

* why it exists
* what it means
* how it works
* when it is useful
* what can go wrong

Do not merely provide definitions.

### 4. Example Integration Test

Examples must be woven into the reasoning.

Do not add examples merely to satisfy a requirement.

Prefer **one strong, well-explained example** over several superficial examples.

### 5. Code Integration Test

Code must appear because the narrative has created a reason to write it.

Before the code:

* explain the problem

During the code:

* explain what we are building

After the code:

* explain what changed
* explain why it works
* connect it back to the original problem

### 6. Compression Test

After completing the episode, attempt to remove approximately **15–20%** of the narration.

If a paragraph can be removed without reducing understanding, remove or consolidate it.

Never preserve filler simply to achieve a target word count.

### 7. Heading-Removal Test

Temporarily remove all headings.

Read the remaining narration from beginning to end.

It should still sound like one experienced instructor naturally teaching the learner.

If it sounds like separate documentation sections joined together, rewrite the transitions.

### 8. Episode Bridge Test

The final part of the episode should create a genuine reason to continue.

Do **not** simply announce:

> "In the next episode, we will learn X."

Instead, leave the learner with the next natural problem, question, or limitation that the following episode will resolve.

---

## Final principle

The goal is **not**:

> "Make every episode longer."

The goal is:

> **"Make every episode feel like a necessary part of one continuous learning journey."**

Narrative quality is more important than word count.

---

## How concepts appear

Every new concept should feel like it became necessary because of something the learner just encountered.

The instructor should:

1. Establish a situation
2. Make the learner notice a problem
3. Ask the question that naturally follows
4. Introduce the Java concept as the answer
5. Use examples as part of that reasoning — not pasted after the explanation

Preferred flow when useful:

**Narrative → explanation → example → code → walkthrough → learner question → deeper explanation → connection → next problem**

Interview checkpoints and practice drills are optional and secondary. Do not interrupt the lesson just to include them.

---

## Runtime guidance (secondary)

Floor about **4 minutes**, soft aim about **10–12**, ceiling about **15** — only when the material earns it.

Shorter is better if the eight quality-gate tests still pass.
